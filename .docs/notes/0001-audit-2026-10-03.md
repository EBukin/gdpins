### High — fix first

#### H1 ✓ Pin name `".."` / `"."` → path traversal and deletion of parent folder
- Where: `R/verbs.R:537` (`gdpins_pin_remove`), `R/verbs.R:100-156` (`gdpins_pin_write`),
  `R/prune.R:200, 231, 238, 240`.
- Problem: name only checked non-empty. `pins:::check_pin_name("..")` passes (rejects slashes
  only). `pin_exists.pins_board_folder` = `dir_exists(path(board$path, name))` → TRUE for `.`/`..`.
- Failure: `gdpins_pin_remove(board, "..")` → `pin_delete` → `fs::dir_delete(<cache_dir>/..)`.
  Default cache → wipes every sibling board's cache. local_only board with
  `cache_dir = "data/pins"` → deletes `data/`. `"."` deletes the whole board.
  `pin_write(board, x, "..")` writes version dirs into the parent.
  `prune(board, "..", dry_run = FALSE, force = TRUE)` lists sibling dirs as "versions" and deletes them.
- Fix: shared `.check_pin_name()` (reject `.`, `..`, `/`, `\`, control chars, leading dot,
  non-scalar, NA); call from every verb, prune, sync.

#### H2 ✓ Drive file names → local path traversal (raw connections)
- Where: `R/raw-connection.R:973-977` (Drive-ID download), `:645-649`, `:664-668`
  (sync_from_drive loop), `:1228-1231` (`gdpins_refresh_disconnect`), `R/sync.R:954-961`
  (`.raw_copy_to_local`). Also `put_object`/`put_file` (`raw-connection.R:712-765`) do not
  validate `name`.
- Problem: Drive names (may contain `..`, `/`, `\`) go straight into `file.path(local_path, ...)`.
- Failure: shared-folder file `..\..\.Rprofile` (Windows) written outside the mirror.
  `put_object(conn, x, "../x.csv")` writes outside `local_path` and creates a Drive folder `..`.
  Vector `name` → obscure "condition has length > 1". `"C:/x.csv"` → invalid path.
- Fix: one helper building local path + `fs::path_has_parent(normalized, local_path)` assert;
  reject `..`, absolute, drive letter, `\` in Drive names. Shared `.check_rel_name()` for put verbs.

#### H3 ✓ Drive name lookups use unescaped regex
- Where: `R/drive-adapter.R:91, 147, 585` — `drive_ls(pattern = paste0("^", part, "$"))`.
- Failure: package's own example name `"quarterly report (Q1 2024).csv"` never matches itself →
  `exists` FALSE, download aborts, upload's `existing` lookup misses → duplicate Drive file on
  every put. `.` matches any char: `a.csv` matches `abcsv`; `hits[1L, ]` may download, update or
  **trash the wrong file**.
- Fix: list folder, compare exactly (`hits[hits$name == part, ]`). Error on >1 match instead of
  `[1L, ]`.
- Related (med): `R/raw-connection.R:414-415` uses `drive_path` as unescaped regex prefix →
  `drive_path = "data (raw)"` never stripped, paths doubled. Fix: `startsWith()` + `substring()`;
  same for adapter-root strip.

#### H4 ✓ Listing/lookup errors swallowed → treated as "absent" → overwrite / duplicates
- Where: `R/sync.R:595-598` (raw), `R/sync.R:220-221` (pins), `R/sync.R:365-368`;
  `R/drive-adapter.R:90-93, 146-149, 202, 584-587, 632` (`tryCatch(..., error = function(e) NULL)`).
- Failure: auth/quota/network/429 error → empty listing → every local file `local_ahead` → real
  adapter `drive_update` replaces newer Drive content with stale local copies. In `.ensure_dir`
  → duplicate folder; upload → duplicate file; `.real_ls_recursive` drops a subtree silently;
  `raw_remove` treats file as absent.
- Fix: only an empty result means absent. Let real errors propagate (optional retry).

#### H5 ✓ Conflict "copy both directions" copies in wrong order
- Where: `R/sync.R:598-599` (versioned) and `:627-628` (`on_conflict = "version"`, unversioned).
- Problem: drive→local first, then local→drive. Second copy reads local *latest*, which is now the
  Drive copy.
- Failure: unversioned → local data overwritten, Drive gets its own data back. Versioned → local
  conflicting version never reaches Drive; next status reports `in_sync`.
- Fix: read both objects first, then write each to the other side.

#### H6 No last-synced baseline → "newer wins" silently overwrites concurrent edits
- Where: `R/sync.R:254-276` (pins), `:396-416` (raw, mtime).
- Problem: compares only latest timestamps; conflict only on equal/NA. No record of last sync.
- Failure: machine A writes offline at T1, machine B writes to Drive at T2 → sync pulls B,
  wiping A on unversioned board; versioned board never pushes A. Raw path also exposed to clock
  skew. Breaks "never silent overwrite" promise.
- Fix (design decision): store per-pin / per-file last-synced hash; conflict when both sides
  differ from it.

#### H7 ✓ Raw conflict default = Drive wins, local overwritten
- Where: `R/sync.R:815-821`.
- Problem: default `on_conflict = "version"` on raw → `.raw_copy_to_local`, info message only.
- Fix: treat `"version"` on raw as `"stop"`, or back up local file (e.g. `<name>.conflict-<ts>`)
  before overwrite.

#### H8 Prune deletes local-only versions without showing them
- Where: `R/prune.R:236-242`.
- Problem: local versions pruned on local's own list, independent of Drive. Offline / unsynced
  versions permanently deleted. Dry run and threshold count primary (Drive) versions only → never
  shown or confirmed.
- Fix: delete local version only if its hash exists on Drive; include local deletions in dry-run
  plan and threshold count.

### Medium

#### Security / auth
- **M1 — `.rds` deserialization from shared Drive.** `R/verbs.R:452` (pins `readRDS`),
  `R/output.R:181`, `R/discovery.R:20`. DESCRIPTION `R (>= 4.1.0)`; anyone with write access to
  the shared folder can plant an rds that runs code on R < 4.4.0 (CVE-2024-27322).
  Fix: `R (>= 4.4.0)` and/or refuse Drive rds pins unless opted in; document trust model.
- **M2 ✓ Cached token ignores `email`.** `R/auth.R:42-44` — `.gd_has_token()` short-circuits.
  Token for a@ cached, `gdpins_real_drive(email = "b@")` → everything runs as a@.
  Fix: compare `googledrive::drive_user()$emailAddress` with `email`; re-auth on mismatch.
  Also `auth.R:46`: `email = NULL` → `if (logical(0))` crash; `NA` passed to `drive_auth`.
- **M3 — Prompt env vars in production.** `R/raw-connection.R:93-103` reads
  `GDPINS_RAW_INTERACTIVE` / `GDPINS_RAW_READLINE`; a leaked value in `.Renviron`/CI auto-answers
  "y" to create/sync prompts. Fix: mockable seam (`local_mocked_bindings`).

#### Drive IDs
- **M4 ✓ `.is_drive_id` rejects hyphens.** `R/drive-adapter.R:567-573` uses `^[A-Za-z0-9_]+$`;
  real IDs often contain `-` → falls to name ladder → "not found". Conversely a 25+ char
  extensionless alphanumeric name is treated as an ID. Roxygen ("no `/`, no spaces") contradicts
  code. Fix: `^[A-Za-z0-9_-]{25,}$` + no extension; fix doc.
- **M5 — Drive ID as `drive_path` stored as path.** `R/raw-connection.R:554-574` (also
  `R/board.R:502`). Later calls build `"<ID>/name"` → `.resolve_real_path` looks for folder
  *named* the ID → `put` creates that folder, `ls` empty. Documented `conn2` example broken.
  Fix: resolve ID to dribble and keep it as connection root, or reject IDs as `drive_path`.
- **M6 — Drive-ID download ignores real location.** `R/raw-connection.R:973-975` → saves to
  `local_path/<name>`; two IDs with same name → second returns first via `file.exists` shortcut
  (wrong data silently); files outside connection pollute mirror. Fix: map ID to path relative to
  connection, or ID-keyed cache dir.

#### Offline / lazy
- **M7 — Offline at first resolve permanently downgrades board.** `R/board.R:466-494` +
  `R/lazy.R:112-115`. Lazy board caches `resolved = TRUE` as `local_only`, contrary to docs
  ("transient network failure does not poison the board"). `drive_board` NULL → offline write
  guard in `gdpins_pin_write` (`verbs.R:113`) never fires → writes local-only silently for the
  session. Fix: don't cache an offline downgrade, or keep `drive_cache` and gate Drive at call time.
- **M8 — `go_offline` on unresolved lazy board stashes broken state.** `R/offline.R:95-101`:
  `x$config` returns declared `"drive_cache"`, then `x$drive_board` forces `.build_board` →
  offline fallback `local_only` (NULL drive_board/adapter). `go_online` rebuilds `drive_cache` with
  no drive_board, prints "reconnected", sync says "nothing to sync" → offline writes never reach
  Drive. Fix: stash from resolved fields; abort if `drive_board` NULL.
- **M9 — `go_online` with new adapter reuses stale `drive_board`.** `R/offline.R:202-211`. Reads
  / writes go to old target, `gd_*` calls to new. `.handle_init_sync` turns sync errors into
  warnings, then success printed anyway. Fix: rebuild via `.build_board` when adapter passed.

#### Board storage / write path
- **M10 — Shared folder for gdrive cache and local board.** `R/board.R:595-601, 516-523`.
  `pin_meta.pins_board_gdrive` writes `cache/<name>/<version>/data.txt` before data arrives →
  metadata call or interrupted download leaves a version dir that `local_board` treats as a real
  pin → `pin_read` local-first fails "Cache failure", falls back to Drive with warning
  (`verbs.R:452-459`); `gdpins_pin_path` returns non-existent path (`pin_download` doesn't check;
  `verbs.R:327-331`). Fix: check files exist in `.pin_sources` / `pin_path`, or separate scratch
  cache. Note: interacts with single-local-copy design (plan §2 Principle).
- **M11 — Write not atomic.** `R/verbs.R:147-156`: two `pins::pin_write` calls, separate
  timestamps → Drive and local can get different version IDs; local failure after Drive success
  (disk full, same-timestamp abort in `version_setup`) → silent drift. Fix: write local once,
  upload that exact version folder; or catch, warn, mark dirty.

#### Sync
- **M12 — `.copy_pin_to_board` failures and metadata loss.** `R/sync.R:703-719`. Source read
  failure warns and returns, caller still counts "synced" (`:642-646`) — includes file-type pins
  `pin_read` can't read. `pin_write` gets only `type`: title, description, user meta, tags, urls
  dropped; `versioned` not passed. Fix: return success flag; copy meta, ideally copy version files.
- **M13 — No per-item error isolation for boards.** `R/sync.R:586-654`: uncaught `pin_write`
  error aborts mid-sync, no summary. Raw path has `attempt`. Fix: reuse `attempt` pattern.
- **M14 — `on_conflict = "stop"` message wrong.** `R/sync.R:667-675, 875-883`: says "Nothing was
  changed" after non-conflicting items already copied. Fix: conflict pre-pass, or fix message.
- **M15 — Conflicts ignore `direction`.** `R/sync.R:684 / 595-636`.
  `go_online(on_discrepancy = "sync_to_drive")` uses default `on_conflict = "version"` → conflicts
  can still pull Drive over local. Fix: restrict conflict resolution by direction, or default
  `"stop"` for one-way.

#### Raw connection
- **M16 — Discrepancy check compares name sets only.** `R/raw-connection.R:633-678`; md5 already
  in listing, unused. `sync_from_drive` overwrites every local file (wipes unsynced edits);
  `sync_to_drive` pushes stale copies; content changes never detected. Fix: per-file md5 compare,
  transfer only differing/missing; never overwrite newer without asking.
- **M17 — Non-atomic local writes.** `R/raw-connection.R:718-724, 763-769, 1064-1067`: mirror
  overwritten before upload; `force_refresh` downloads over local file → failed upload leaves
  local ≠ Drive (undetected per M16); interrupted download → truncated file. Fix: download to
  temp + `file_move`; upload first then copy locally, or record dirty state.

#### Type round-trip
- **M18 — Parquet default drops row names / attributes / subclasses.** `R/io-formats.R:421-438`
  + `verbs.R:484`. Example `gdpins_pin_write(board, mtcars, "cars")` loses car names.
  Fix: choose rds when `.row_names_info(x) > 0` or extra attributes/classes present.
- **M19 — Active geometry not recorded.** `R/io-formats.R:240` + `:142-165`; `st_sf()` makes
  first restored geometry active. Fix: record active column (name marker or pin meta), restore
  via `st_set_geometry`.
- **M20 — Geometry parse warning discards result.** `R/io-formats.R:218-222`
  (`warning = function(w) NULL`) → column silently stays WKT with suffixed name. Fix: catch errors
  only; let/re-emit warnings.

#### Memory
- **M21 — `gdpins_pin_info` reads full pin for column names.** `R/discovery.R:18-21`. Fix:
  `nanoparquet::read_parquet_schema()` on file from `pin_download`.
- **M22 — `publish_output` loads every pin and re-saves as rds.** `R/output.R:180-187`; parquet
  format lost, sf stays WKT, peak memory = largest pin. Fix: upload stored files from
  `pins::pin_download` as-is.

#### Test seam
- **M23 — Fake adapter diverges from real Drive.** `R/drive-adapter.R:298-304, 319-330, 389-391,
  651-653`: `upload` never clears `state$trash[[path]]` (put → remove → put → `exists` FALSE,
  download aborts "in trash"); `startsWith` exclusion hides `a.csv.bak` after `a.csv` trashed and
  `sub2/...` after `sub`; trash key `gsub("/", "_")` collides `a/b.csv` vs `a_b.csv`.
  Fix: clear key on upload/mkdir; match `rp == tk | startsWith(rp, paste0(tk, "/"))`; unique dir
  per trash entry.
- **M24 — Fake `ls` returns absolute paths on Windows.** `R/drive-adapter.R:383` /
  `R/raw-connection.R:400-411`: escaped backslash root never matches `fs` `/` paths; breaks
  relative-path contract; trash filter becomes no-op; 8.3 short tempdir also breaks it; `.rel`
  dead code. Fix: `fs::path_rel(all_paths, root)` in adapter; drop root stripping in
  `.gd_ls_to_rel`.

### Low / design

- **L1 ✓ `version` arg of `gdpins_pin_write` ignored.** `R/verbs.R:520-525` (pre-refactor
  `:125-130`): both branches identical. Implement or deprecate + error when non-NULL.
- **L2 — `drive_path` not validated.** `R/board.R:330-408, 48-61`: vector uses first element;
  `""` maps to `<root>/<key>` shared with other boards; sanitiser maps `"a b"`/`"a_b"` (and case
  on Windows) to same folder. Fix: non-NA non-empty scalar check; append short hash of raw
  `drive_path` to cache dir. Relevant to single-local-copy `.default_cache_dir()`.
- **L3 — `gdpins_pin_info` print fails for multi-file pins.** `R/discovery.R:161, 184-185`:
  `size` vector → `gd_fmt_bytes` aborts. Fix: `sum(meta$file_size)` (as `gdpins_list_pins`).
- **L4 — Glob mode lists local copy only.** `R/discovery.R:79` vs `R/verbs.R:179-200`: Drive-only
  pin invisible to `pin_read(board, "*")`. Fix: union across `.pin_sources`.
- **L5 — Prune messages / threshold.** `R/prune.R:205` prints "{keep} present" (wrong count);
  "Pruned {n_remove}" reports primary count; board-level threshold only per pin (100 pins × 9
  versions removed without confirmation). Fix: real counts; total vs threshold.
- **L6 — `raw_path("sub")` can return a directory.** `R/raw-connection.R:985 / 204-217`:
  `.local_exists_exact` TRUE for dirs, breaks "file guaranteed".
- **L7 — `gdpins_refresh_disconnect` invalidates nothing** and doesn't remove local files deleted
  on Drive (`R/raw-connection.R:1212-1236`).
- **L8 — `on_discrepancy = "prompt"` never prompts.** `R/board.R:150-166`.
- **L9 — `gdpins_board_connect` override permanent.** Docs say "for this connection only", but it
  mutates `state$spec` (`R/lazy.R:225`).
- **L10 — `pin_read` offline returns NULL + warning** instead of erroring (`R/verbs.R:447`); NULL
  flows into pipelines.
- **L11 — `gdpins_publish_output` calls `gdpins_is_online()` without the usual `tryCatch`**
  (`R/output.R:136`).
- **L12 — Deletions never propagate.** Pin/file removed on one side returns on next sync.
- **L13 — Duplication.** Three "local-first" helpers (`.read_source` discovery.R:12,
  `.resolve_read_board` output.R:215, `.pin_sources`); board build duplicated (Drive-ID fast path
  `board.R:502-539` vs `:578-633`); local rel-path computation (`raw-connection.R:620-627` vs
  `1177-1184`) and sync-download loop (`:645-649` vs `:664-668`) copied. Fix: `fs::path_rel`,
  single `.raw_pull(conn, files)`.

4. Coordinate M10, L2 with single-local-copy plan (`tools/plan-single-local-copy.md`) before T3+.
